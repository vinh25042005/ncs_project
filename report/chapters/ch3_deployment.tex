\section{Cấu hình Dual-ENI cho máy chủ Gateway}
Mỗi máy chủ Gateway được trang bị 2 card mạng Dual-ENI độc lập phục vụ định tuyến và phân tách mạng:
\begin{lstlisting}[language=bash, caption={Khai báo Dual-ENI cho Gateway trong Terraform}]
resource "aws_instance" "gateway" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.small"

  network_interface {
    network_interface_id = aws_network_interface.gateway_wan.id # Card ens5 Public Subnet
    device_index         = 0
  }
  network_interface {
    network_interface_id = aws_network_interface.gateway_lan.id # Card ens6 Private Subnet
    device_index         = 1
  }
}
\end{lstlisting}

\section{Cấu hình Gateway, HAProxy Layer 4 và Suricata IDS/IPS}
\subsection{Định tuyến mạng và cấu hình IPTables NAT}
Kích hoạt chuyển tiếp gói tin, thiết lập Policy Routing qua Netplan để chống định tuyến bất đối xứng và cấu hình bảng IPTables:
\begin{lstlisting}[language=bash, caption={Cấu hình IPTables SNAT và DNAT trên Gateway}]
# Kich hoat Linux IP Forwarding
sudo sysctl -w net.ipv4.ip_forward=1

# Chuyen tiep cong 8443 vao Wazuh SIEM Dashboard tren may chu rieng biet
sudo iptables -t nat -A PREROUTING -i ens5 -p tcp --dport 8443 -j DNAT --to-destination 10.0.20.10:443

# Mo cong INPUT cho HAProxy tiep nhan truc tiep luong HTTP, HTTPS, Rancher va Stats
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443,7443,8404 -j ACCEPT

# Cau hinh Source NAT Masquerade cho luong Egress ra ngoai Internet
sudo iptables -t nat -A POSTROUTING -o ens5 -j MASQUERADE
sudo iptables -t nat -A POSTROUTING -o ens6 -j MASQUERADE
\end{lstlisting}

\subsection{Cấu hình bộ cân bằng tải HAProxy Layer 4}
HAProxy được cài đặt và quản trị tập trung qua Ansible trên cả hai Gateway. Cấu hình vận hành ở chế độ \texttt{mode tcp} (Layer 4 Stream), tích hợp kiểm tra sức khỏe chủ động và cơ chế Active/Backup:
\begin{lstlisting}[language=bash, caption={Cấu hình HAProxy Layer 4 trên Gateway 1 (haproxy.cfg)}]
global
    log /dev/log local0
    stats socket /run/haproxy/admin.sock mode 660 level admin
    stats timeout 30s
    user haproxy
    group haproxy

defaults
    log     global
    mode    tcp
    option  tcplog
    timeout connect 5000ms
    timeout client  50000ms
    timeout server  50000ms

# Frontends va Backends cho HTTP (Cong 80)
frontend http_in
    bind *:80
    default_backend http_nodes

backend http_nodes
    mode tcp
    balance roundrobin
    server worker1 10.0.10.139:80 check inter 2s rise 2 fall 2
    server worker2 10.0.11.21:80 check inter 2s rise 2 fall 2 backup

# Frontends va Backends cho HTTPS (Cong 443)
frontend https_in
    bind *:443
    default_backend https_nodes

backend https_nodes
    mode tcp
    balance roundrobin
    server worker1 10.0.10.139:443 check inter 2s rise 2 fall 2
    server worker2 10.0.11.21:443 check inter 2s rise 2 fall 2 backup

# Frontends va Backends cho Rancher (Cong 7443)
frontend rancher_in
    bind *:7443
    default_backend rancher_nodes

backend rancher_nodes
    mode tcp
    server master 10.0.10.10:30443 check inter 2s rise 2 fall 2

# Dashboard thong ke HAProxy Stats
listen stats
    bind *:8404
    mode http
    stats enable
    stats uri /haproxy?stats
    stats refresh 5s
\end{lstlisting}
Trên Gateway 2, cấu hình đảo ngược vai trò ưu tiên nhằm tối ưu hóa độ trễ cục bộ theo từng Availability Zone: \texttt{worker2} là Active chính và \texttt{worker1} đóng vai trò \texttt{backup}.

\subsection{Cấu hình luật phát hiện tấn công cho Suricata}
Suricata lắng nghe trên card WAN \texttt{ens5} ở chế độ \texttt{af-packet} với tập luật \texttt{local.rules}:
\begin{lstlisting}[language=bash, caption={Tập luật phát hiện tấn công trong local.rules của Suricata}]
# Nhan dien SQL Injection (UNION SELECT, OR 1=1)
alert http any any -> any any (msg:"ATTACK: SQL Injection Union Select Detected"; flow:to_server,established; content:"UNION"; nocase; content:"SELECT"; nocase; sid:1000001; rev:1;)
alert http any any -> any any (msg:"ATTACK: SQL Injection OR 1=1 Detected"; flow:to_server,established; content:"or"; nocase; content:"1=1"; sid:1000002; rev:1;)

# Nhan dien Directory Traversal (/etc/passwd, ../..)
alert http any any -> any any (msg:"ATTACK: Directory Traversal /etc/passwd Detected"; flow:to_server,established; content:"/etc/passwd"; sid:1000003; rev:1;)
alert http any any -> any any (msg:"ATTACK: Directory Traversal Path Manipulation"; flow:to_server,established; content:"../.."; sid:1000004; rev:1;)

# Nhan dien Cross-Site Scripting (XSS)
alert http any any -> any any (msg:"ATTACK: XSS Payload Detected"; flow:to_server,established; content:"<script>"; nocase; sid:1000005; rev:1;)

# Nhan dien do quet tep tin he thong nhay cam (.env, .git)
alert http any any -> any any (msg:"ATTACK: Sensitive File Probe (.env/.git)"; flow:to_server,established; content:".env"; sid:1000006; rev:1;)
\end{lstlisting}

\section{Khởi tạo cụm Upstream Kubernetes v1.31}
Khởi tạo Control Plane trên Master node và kết nối các Worker nodes qua \texttt{kubeadm}:
\begin{lstlisting}[language=bash, caption={Lệnh khởi tạo Control Plane và kết nối Worker nodes}]
# Tren Master Node: khoi tao Control Plane tich hop Audit Policy
sudo kubeadm init --config /etc/kubernetes/kubeadm-config.yaml

# Tren Worker 1 va Worker 2: ket noi vao cum
sudo kubeadm join 10.0.10.10:6443 --token <token> --discovery-token-ca-cert-hash <hash>
\end{lstlisting}

\section{Triển khai Cilium eBPF và Hubble UI}
Cài đặt Cilium v1.16.2 chế độ eBPF Kernel Mode và kích hoạt Hubble UI qua Cilium CLI:
\begin{lstlisting}[language=bash, caption={Lệnh cài đặt Cilium eBPF và Hubble UI}]
/usr/local/bin/cilium install \
  --version 1.16.2 \
  --set ipam.mode=kubernetes \
  --set routingMode=tunnel \
  --set tunnelProtocol=vxlan \
  --set hubble.relay.enabled=true \
  --set hubble.ui.enabled=true \
  --wait=false

# Chuyen Service Hubble UI sang NodePort tren cong 31235
kubectl patch service hubble-ui -n kube-system \
  -p '{"spec": {"type": "NodePort", "ports": [{"name": "http", "port": 80, "targetPort": 8081, "nodePort": 31235}]}}'
\end{lstlisting}

\section{Triển khai Ingress-NGINX và Rancher Server}
\subsection{Ingress-NGINX Controller}
Triển khai Ingress-NGINX ở chế độ Multi-AZ Active-Active với 2 Replicas trên cả hai Worker node (\texttt{10.0.10.139} và \texttt{10.0.11.21}) sử dụng nhãn \texttt{ingress-ready: "true"} và \texttt{hostNetwork: true}, kết hợp khai báo Ingress manifest:
\begin{lstlisting}[language=yaml, caption={Khai báo Ingress cho ứng dụng Online Boutique}]
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: boutique-ingress
  namespace: online-boutique
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/proxy-body-size: "10m"
    nginx.ingress.kubernetes.io/limit-rps: "50"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - boutique.lab
      secretName: boutique-tls
  rules:
    - host: boutique.lab
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend
                port:
                  number: 80
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend
                port:
                  number: 80
\end{lstlisting}

\section{Triển khai Google Online Boutique và Network Policies}
Ứng dụng Online Boutique được triển khai trong namespace \texttt{online-boutique}. Áp dụng chính sách cách ly Zero-Trust cho \texttt{paymentservice}:
\begin{lstlisting}[language=yaml, caption={Chính sách NetworkPolicy Zero-Trust bảo vệ PaymentService}]
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: paymentservice-zero-trust
  namespace: online-boutique
spec:
  podSelector:
    matchLabels:
      app: paymentservice
  policyTypes:
    - Ingress
    - Egress
  ingress:
    # Chi chap nhan ket noi den tu CheckoutService qua cong gRPC 50051
    - from:
        - podSelector:
            matchLabels:
              app: checkoutservice
      ports:
        - protocol: TCP
          port: 50051
  egress:
    - to:
        - namespaceSelector: {}
          podSelector:
            matchLabels:
              k8s-app: kube-dns
      ports:
        - protocol: UDP
          port: 53
\end{lstlisting}

Áp dụng CiliumNetworkPolicy cho phép Ingress host traffic tới \texttt{frontend}:
\begin{lstlisting}[language=yaml, caption={Chính sách CiliumNetworkPolicy cho phép Ingress host traffic tới Frontend}]
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: allow-ingress-host-to-frontend
  namespace: online-boutique
spec:
  endpointSelector:
    matchLabels:
      app: frontend
  ingress:
    - fromEntities:
        - host
        - remote-node
      toPorts:
        - ports:
            - port: "8080"
              protocol: TCP
\end{lstlisting}

\section{Triển khai Wazuh SIEM và tích hợp Agent}
Wazuh SIEM được cài đặt trên máy chủ \texttt{10.0.20.10} trong Management Subnet:
\begin{enumerate}
    \item \textbf{Wazuh Manager \& Indexer}: Vận hành công cụ tương quan và OpenSearch Indexer, cung cấp web Dashboard trên cổng 443.
    \item \textbf{Wazuh Agents}: Đăng ký 5 Agent cho Gateway 1, Gateway 2, Master, Worker 1, Worker 2. Cấu hình thu thập log Suricata và K8s Audit:
\begin{lstlisting}[language=xml, caption={Khai báo nguồn log trong cấu hình Wazuh Agent}]
<!-- Tren Gateway: Thu thap log Suricata eve.json -->
<localfile>
  <log_format>json</log_format>
  <location>/var/log/suricata/eve.json</location>
</localfile>

<!-- Tren Master: Thu thap K8s API Server audit.log -->
<localfile>
  <log_format>json</log_format>
  <location>/var/log/kubernetes/audit.log</location>
</localfile>
\end{lstlisting}
\end{enumerate}
